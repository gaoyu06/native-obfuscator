**Accept the phase-16 Java-bytecode-to-C++ change.**

No correctness miscompile was found in the requested `SWAP`, `AALOAD`, or
`AASTORE` scope, so this review is documentation-only and makes no compiler
change. The focused tests, retained generated C++ unit, and independent GNU C++
syntax check pass. This is not a production-readiness approval: the IR mode
remains opt-in, and the focused checks do not replace supported-platform CI or
native runtime-parity testing.

## `SWAP`

- The complete stack-type pass reads both operands with `get`, verifies that
  both have one JVM slot, and only then exchanges them. `I32`, `F32`, and
  `REFERENCE` are therefore accepted in all nine ordered pairings.
- `I64` and `F64` each have two JVM slots. The focused rejection test places
  each category-two kind in both the top and next-to-top position; rejection is
  reported at opcode 95 before method, output, metadata, or cache mutation.
- Lowering repeats the two-operand width guard and exchanges the two existing
  `IrValue` references. It does not create an IR instruction or result value.
  Consequently the direct IR body introduces no temporary or JNI call for
  `SWAP`; successor stack phis consume the reordered state.
- The retained smoke unit contains three representative mixed-carrier
  functions. Their direct IR bodies consist of a block label and
  `return arg1;`; the surrounding JNI shell boilerplate is not generated by
  `SWAP`.

## Shared array nodes and emission

- `IrNodes.ArrayLoad` derives its element carrier from its result, and
  `IrNodes.ArrayStore` derives it from its value. Their constructors admit only
  `I32` or `REFERENCE`, while requiring a `REFERENCE` array and an `I32` index.
- `AsmToIr` creates an `I32` result/value for `IALOAD`/`IASTORE` and a
  `REFERENCE` result/value for `AALOAD`/`AASTORE`.
- `IrCppEmitter` branches on that validated element carrier.
  `GetObjectArrayElement` and `SetObjectArrayElement` occur only for
  `REFERENCE`; `GetIntArrayRegion` and `SetIntArrayRegion` occur only for
  `I32`. The emitter cannot silently select the object operation for an
  integer node or the integer operation for a reference node.

## Pending exceptions

- A null array is checked before either reference-array JNI call.
  `utils::throw_re` creates the pending `NullPointerException`, followed by the
  block's ordinary exceptional exit.
- For a non-null array, JNI performs the bounds check.
  `GetObjectArrayElement`/`SetObjectArrayElement` is followed immediately by
  `ExceptionCheck`; a negative index or `index == length` therefore routes the
  pending `ArrayIndexOutOfBoundsException` without using a result.
- `SetObjectArrayElement` performs the reference-component compatibility check.
  A value incompatible with a `String[]` routes the JNI-raised
  `ArrayStoreException`.
- Unprotected exits return with the JNI exception still pending. For an
  in-method handler, the shared dispatcher first saves it with
  `ExceptionOccurred`, then clears it so Java catch matching and handler
  execution can proceed. If no handler matches, it calls `Throw` on that same
  saved throwable before returning. There is no `ExceptionClear` between a
  phase-16 JNI call and entry into this dispatcher, and no pending exception is
  silently discarded or replaced.
- `AALOAD` assigns the loaded reference to its SSA result only after the
  exception check succeeds.

## Fallback and retained behavior

`IrMethodCompiler` completes frontend validation and C++ body construction
before `MethodShellEmitter.beginIr` mutates the method or appends generated
state. The phase-16 fallback regression executes admitted `AASTORE`, `AALOAD`,
and `SWAP` in bytecode order, then reaches unsupported `POP2` (opcode 88). It
confirms no `ACC_NATIVE`, C++ output, native metadata, or class/string/field/
method cache mutation.

The phase-16 diff adds five tests and does not remove the phase-9 through
phase-15 regressions. The same `IrCompilerTest` suite retains the earlier array
return, field and invoke carrier, constructor, scalar floating-point, and LDC
checks. `CodegenModeTest.cliDefaultsToLegacy`, `Main`'s
`defaultValue = "legacy"`, and the API overload delegating to
`CodegenMode.LEGACY` remain present.
`obfuscator/src/main/resources/sources/cppsnippets.properties` also remains
present.
