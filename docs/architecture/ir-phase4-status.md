# IR phase 4 status

This branch extends `cursor/ir-phase3-fable-review-6d81` with the first
exception-aware slice of the opt-in typed CFG compiler. The CLI/API default
remains `legacy`; `--codegen=ir` still falls back independently for methods
outside the supported subset. The legacy snippet path is unchanged.

Preferred PR merge base:
`cursor/ir-phase3-fable-review-6d81` at

## What landed

### Exception-aware CFG

- Try-region starts/ends and handler labels are basic-block boundaries.
- Potentially throwing instructions end a block, and `ATHROW` is a terminator
  without a normal fallthrough edge.
- Each protected CFG/IR block carries its exception-table entries in JVM order
  as `ExceptionEdge` / `IrExceptionEdge` values. A null catch type represents a
  catch-all entry.
- Reachability follows normal and exceptional successors, so handler blocks are
  retained.
- Duplicate catch types are treated like the legacy `CatchesBlock` path: the
  first matching table entry is retained for dispatch.

### Typed frontend and SSA

- A handler entry receives exactly one `Ref` stack value, produced by the new
  `CaughtException` instruction.
- Locals merge into handler phis across exceptional predecessors. The frontend
  re-checks carrier identity on those edges just as it does on normal edges.
- `ASTORE` is included as the minimal stack-to-local operation needed by normal
  Java catch-handler prologues.
- `ATHROW` lowers to the new typed `Throw` terminator and requires a reference.
- Handler entries that also have reachable normal predecessors are rejected in
  `AsmToIr.build(...)`; malformed/empty exception regions and all unsupported
  handler instructions are rejected there as well.

### Structured C++ catch dispatch

Every protected JNI operation now routes a pending exception to the block's
shared handler-set dispatch instead of returning zero and bypassing a catch.
This includes null checks and the phase-3 `GetIntArrayRegion` /
`SetIntArrayRegion` bounds path.

The emitter:

1. copies exceptional-edge local phi inputs while still in the throwing block;
2. goes to one `IR_CATCH_n` label per distinct ordered handler set;
3. captures `jthrowable caught_exception = env->ExceptionOccurred()` and calls
   `env->ExceptionClear()`;
4. evaluates the handler types in order with `env->IsInstanceOf`;
5. enters the selected handler, where `CaughtException` supplies the `jobject`
   SSA value; or
6. calls `env->Throw(caught_exception)` and returns the JNI default when no
   handler matches.

Catch-all dispatch jumps directly to its handler. SSA carriers and
`caught_exception` are function-level uninitialized declarations; initialized
edge and array temporaries remain inside scopes that a function-level `goto`
only exits. The emitted types are JNI types (`jobject`, `jclass`, `jthrowable`,
and existing primitive carriers).

Handler class caching continues to use the shared method shell and existing
cache arrays. Dispatch is generated by the structured `CppAst` emitter; the
legacy `TRYCATCH_*` snippets and `MethodProcessor` catch epilogue were not
removed or replaced.

## Fallback-before-mutation

Method shape, opcode admission, local/stack typing, handler shape, reachability,
definite locals, lowering, and normal/exception phi connections all complete in
`AsmToIr.build(...)`. Capability misses throw
`UnsupportedIrConstructException` before `IrCppEmitter.emitBody(...)` allocates
cache IDs and before `MethodShellEmitter.beginIr(...)` changes `output`,
`nativeMethods`, or `ACC_NATIVE`.

`rejectsIntStoreIntoInstanceReceiverLocal` remains the regression proof: after a
rejection, the method is not native, generated output/native-method text is
empty, and class/field/method caches remain untouched.

## What still falls back per method

Phase 4 is not full JVM exception parity. Fallback remains for:

- malformed/empty exception regions and handler entries with a reachable normal
  predecessor;
- any try/catch or nested/finally body containing unsupported operations,
  including monitor enter/exit; nested supported regions are accepted only when
  they fit the same CFG/SSA model;
- `jsr`/`ret`, switches, `POP`, and other unlisted stack/control operations;
- static fields, reference fields, and non-`I` fields;
- `long`/`float`/`double`, wide primitives, their arithmetic/conversions, and
  `IDIV`/`IREM`;
- reference/void/wide-returning invokes, unsupported primitive arguments,
  `INVOKESPECIAL`, `INVOKEINTERFACE`, and `invokedynamic`;
- object and array creation (`new`, constructor calls, `newarray`,
  `anewarray`, and `multianewarray`);
- non-`int` array element loads/stores, reference stores/returns, casts, and
  ordinary bytecode type tests;
- library intrinsics beyond the existing `String.length()` slice; and
- every other opcode or descriptor shape not listed in the phase 1–4 status
  documents.

These methods continue through per-method legacy fallback on clean shared state.
The branch is not production-ready without broader opcode coverage, runtime
parity validation, and review.
