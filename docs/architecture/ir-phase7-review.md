## Findings

### Typed IR and frontend invariants

- `CheckCast` requires a reference operand and produces a reference result.
  `InstanceOf` requires a reference operand and produces `I32`. Both retain the
  exact ASM type operand.
- `CfgBuilder` treats both operations as potentially throwing, so protected
  operations end a block with the ordered handler set attached.
- `I64` uses the real JNI `jlong` carrier and a JVM width of two. Long
  parameters advance local numbering by `Type.getSize()`, and a long local's
  continuation slot is recorded and validated. Truncated and overlapping wide
  locals are rejected.
- Stack analysis keeps logical typed values while stack phi metadata advances
  by each value's physical JVM slot width. The regression confirms that an
  `I32` above an `I64` receives physical stack slot index 2.
- `LLOAD`, `LSTORE`, `LCONST_0/1`, `LADD`, `LSUB`, `LMUL`, `LRETURN`, `I2L`,
  and `L2I` are admitted and type-checked. Other long operations remain
  unsupported per method.

### Independently inspected generated C++

The retained 29-method translation unit generated by the focused test was read
directly. The relevant emitted behavior is:

- Ordinary `CHECKCAST` resolves its target class, then tests only a non-null
  operand. A mismatch calls `utils::throw_re` with
  `java/lang/ClassCastException`; a successful or null operand is copied
  unchanged to the reference result.
- Protected `catchCast` sends class-resolution and cast-failure exceptions to
  `IR_CATCH_0`. The dispatcher obtains and clears the pending exception, tests
  it against the ordered catch type, enters the handler on a match, and
  rethrows on no match.
- `INSTANCEOF` assigns its `jint` result to zero before a non-null guard and
  invokes `JNIEnv::IsInstanceOf` only inside that guard, so null produces 0.
- The `[Ljava/lang/String;` target remains unchanged and is passed to
  `JNIEnv::FindClass`; it does not use the ordinary classloader-name resolver.
- `longArithmetic(JJ)J` has `jlong` parameters, `jlong` SSA carriers, and a
  `jlong` return. Its add, subtract, and multiply cast both operands to
  `uint64_t` before the operation and cast the wrapped result to `jlong`.
  The fixture stores and reloads a long at physical locals 4 and 5 before
  emitting `LADD`, `LSUB`, `LMUL`, and `LRETURN`.
- No `juint` or `julong` occurs in the translation unit. The emitted carriers
  are JNI-defined types; `uint64_t` is used only for defined-width unsigned
  arithmetic.

### Fallback before mutation and default mode

`IrMethodCompiler.processMethod` performs:

1. `AsmToIr.build(...)`
2. `IrCppEmitter.emitBody(...)`
3. `MethodShellEmitter.beginIr(...)`

Complete opcode admission occurs near the start of `AsmToIr.build`, before IR
construction and before the emitter can allocate cache/string IDs. The mixed
wide fixture places supported `LLOAD`, `LCONST_1`, and `LMUL` before
unsupported `LDIV`. It is rejected with opcode `LDIV` while `ACC_NATIVE`,
generated output, native-method metadata, and class/string/field/method caches
all remain untouched.

The CLI option still declares `defaultValue = "legacy"`, and the API overload
without an explicit mode still passes `CodegenMode.LEGACY`. IR remains opt-in.
